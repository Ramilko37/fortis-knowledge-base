# Локальный Codex-плагин памяти поверх claude-mem

## Статус

Черновик к реализации

## Контекст

`claude-mem` установлен локально и его worker отвечает на `http://127.0.0.1:37701`, но текущий Codex Desktop не подхватывает его hooks напрямую. Похоже, существующая интеграция ориентирована на Claude Code и Codex CLI, а не на desktop runtime.

Нужен локальный адаптер только для личного использования в Codex Desktop.

## Цель

Создать небольшой локальный Codex-плагин, который даст Codex Desktop доступ к уже работающему `claude-mem` через MCP-инструменты.

## Не цели

- Не форкать весь `claude-mem`.
- Не публиковать плагин.
- Не заменять `knowledge-base/`.
- Не писать автоматические hooks для каждого действия Codex в первом MVP.
- Не хранить секреты, `.env`, токены или приватные ключи.

## Архитектура MVP

```text
Codex Desktop
  -> local Codex plugin
  -> MCP server
  -> claude-mem worker на 127.0.0.1:37701
  -> ~/.claude-mem
```

Плагин будет локальным каталогом в `~/.codex/plugins/codex-local-memory`.

## Инструменты MVP

- `memory_health` — проверить, жив ли `claude-mem` worker.
- `memory_search` — искать по памяти через доступный search API или MCP server `claude-mem`.
- `memory_add` — вручную сохранить важное наблюдение, если API это поддерживает; иначе вернуть явную ошибку с описанием ограничения.
- `memory_recent` — показать последние записи, если API это поддерживает; иначе вернуть понятную ошибку.

## Поведение при ошибках

- Если worker не отвечает, tool возвращает команду восстановления: `npx claude-mem start`.
- Если endpoint отсутствует или несовместим, tool возвращает диагностическое сообщение и не падает молча.
- Если запрос похож на секрет, tool отказывается сохранять его.

## Правило Fortis

`claude-mem` и локальный Codex-плагин используются как рабочая память агента. Официальные решения, контракты и требования по-прежнему фиксируются в `knowledge-base/`.

Если из памяти находится архитектурное или продуктовое решение, агент должен предложить перенести его в базу знаний.

## Проверка

- Worker `claude-mem` отвечает на `memory_health`.
- Codex Desktop видит MCP-инструменты после перезапуска.
- `memory_search` возвращает контролируемый результат или понятную ошибку, если API `claude-mem` не предоставляет нужный endpoint.
- Установка не меняет репозитории Fortis, кроме этой design-записи и будущих документированных решений.
