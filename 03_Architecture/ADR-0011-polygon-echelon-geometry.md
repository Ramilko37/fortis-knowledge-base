# ADR-0011: произвольная polygon-геометрия эшелонов

**Дата:** 2026-06-17  
**Статус:** Accepted

## Контекст

До этой итерации рабочий GIS-сценарий Fortis фактически описывал эшелоны как круговые зоны/кольца вокруг `DefenseProject.baseObject.center`. Это остаётся быстрым и дефолтным режимом, но для промышленных объектов сложной формы нужен контур, который пользователь задаёт точками на карте.

## Решение

- `DefenseProject.layers[].geometry` остаётся источником правды для геометрии эшелона.
- Круговой сценарий сохраняется через существующие `circle`/legacy `ring`-геометрии.
- Добавлен режим `polygon`: пользователь рисует контур точками, замыкает его и сохраняет эшелон.
- Для импортированных legacy-слоёв без `geometry` frontend выполняет runtime fallback в `ring` из старых радиусных полей.
- Состав эшелона не хранится внутри слоя: он по-прежнему выводится через `DefenseProject.placedObjects.filter(object => object.layerId === layer.id)`.
- Для `polygon` размещение объектов ограничено проверкой `isPointInPolygon`; объект вне контура не создаётся.
- `multiPolygon`, GeoJSON import/export, snapping и полноценный topology engine не входят в это решение.

## Последствия

- Backend-совместимость не требует отдельной миграции, пока backend сохраняет полный `projectJson` без потерь и уважает `DefenseProject.schemaVersion = 1`.
- Калькулятор продолжает считать стоимость и структуру по `placedObjects`, независимо от формы эшелона.
- Отчёт должен показывать форму эшелона; для polygon допустима приблизительная площадь, рассчитанная lightweight helper-ом.
- Будущие проверки конфликтов между polygon-эшелонами можно развивать отдельно, не меняя источник состава эшелона.
