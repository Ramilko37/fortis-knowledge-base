# Спецификация 02: геоданные, покрытие и ограничения применения

**Статус:** предложена 2026-07-13.
**Зависимости:** [[01_Requirements/Спецификация_00_Базовый_контракт_и_методики]], [[01_Requirements/Спецификация_01_Каталог_средств_и_ТТХ]], [[03_Architecture/ADR-0011-polygon-echelon-geometry|ADR-0011]].

## Цель

Перевести GIS из визуального прототипа в проверяемую пространственную модель: она учитывает зоны покрытия, жилую застройку, барьеры и радиоэлектронную совместимость.

## Геоданные проекта

Проект получает версионируемые слои: граница предприятия, здания/высоты, лес, жилые зоны, запрещённые зоны, рельеф и пользовательские препятствия. У каждого слоя есть геометрия, тип, источник, дата, точность и видимость. Геоданные не смешиваются с UI-only слоями карты.

## Расчёт покрытия

Backend строит геометрию покрытия из `PlacedDefenseObject` и его ТТХ: круг, сектор, линия либо полигон. Расчёт принимает во внимание разрешённое направление, дальность, геометрию эшелона и утверждённую методику влияния барьеров. В ответе доступны:

```ts
type CoverageResult = {
  objectId: string;
  geometry: GeoJSON.Geometry | null;
  visibility: "all" | "selected" | "hidden";
  degradedBy: string[];
  dataQuality: "confirmed" | "estimated" | "demo";
};
```

Frontend только визуализирует эту геометрию, не пересчитывает её отдельной формулой.

## Правила ограничений

1. МОГ и направленное вооружение не могут получить `allowed`, если сектор поражения пересекает жилую или запрещённую зону.
2. Размещение должно соответствовать геометрии и lock/visibility правилам активного эшелона.
3. РЭБ-конфликт определяется утверждённой методикой по спектру, дистанции, мощности и защищаемым системам.
4. Барьер может дать `warning`, `blocked` или уменьшить coverage — политика задаётся методикой и возвращается с причиной.

Результаты не ограничиваются булевыми `hasCoverageConflict`/`hasTerrainConflict`: они содержат конкретные объекты, геометрии и объяснение из [[01_Requirements/Спецификация_00_Базовый_контракт_и_методики|Spec 00]].

## API и UX

- Server API принимает versioned project/geodata snapshot и возвращает coverage plus `EvaluationResult`.
- На карте можно показать покрытие всех, выбранного объекта или типа защиты; слои эшелона, типа и объекта управляются независимо.
- Warning открывает список причин, фокусирует карту на проблеме и ведёт в инспектор объекта.
- `blocked` предотвращает сохранение операции; `warning` требует применить утверждённую политику.

## Критерии приёмки

- Fixture с жилой зоной блокирует опасный сектор МОГ и показывает границу пересечения.
- Fixture с препятствием изменяет coverage строго по утверждённой методике.
- Fixture с конфликтующими РЭБ возвращает идентичные причины через API, карту и отчёт.
- Контрактные тесты исключают расхождение frontend и backend результатов.
