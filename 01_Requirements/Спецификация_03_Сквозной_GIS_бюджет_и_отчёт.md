# Спецификация 03: сквозной GIS-поток, бюджет и отчёт

**Статус:** предложена 2026-07-13.
**Зависимости:** [[01_Requirements/Спецификация_00_Базовый_контракт_и_методики]], [[01_Requirements/Спецификация_01_Каталог_средств_и_ТТХ]], [[01_Requirements/Спецификация_02_Геоданные_покрытие_и_ограничения]].

## Цель

Закрыть основной пользовательский путь ТЗ: выбрать предприятие → собрать конфигурацию на карте → увидеть ограничения и бюджет → сохранить/сравнить варианты → выгрузить отчёт.

## Обязательный workflow

1. Пользователь открывает серверный проект предприятия и видит явное состояние `saved`, `saving`, `offline draft`, `conflict` или `error`.
2. Выбирает эшелон и средство из compatible-first каталога; карта показывает доступное покрытие и ограничения.
3. Перед размещением backend проверяет бюджет и spatial evaluation. `blocked` не создаёт объект; warning оформляется согласно политике Spec 00.
4. Размещённый объект одновременно появляется на карте, в дереве, инспекторе, калькуляторе и server version проекта.
5. Пользователь сохраняет несколько вариантов, сравнивает их по стоимости, покрытию, предупреждениям и остаточному риску.
6. Отчёт формируется из backend payload конкретной версии проекта.

## GIS-операции и доступность

- Видимость на уровнях: эшелон, тип, объект, покрытие.
- Легенда, basemap, reset extent/bearing и измерение расстояния имеют либо рабочее поведение, либо не отображаются.
- Панели освобождают карту при закрытии; destructive delete подтверждается или имеет undo.
- Есть табличное представление объектов с координатами, статусом, конфликтами и стоимостью.
- Основной desktop flow проходит keyboard-only; предусмотрены loading, empty, offline, API-error и 409 states.

## Бюджет и сравнение

Бюджет принадлежит проекту/предприятию, а не UI-константе. API возвращает лимит, израсходованную сумму, остаток, выбранную политику и результаты проверки новой позиции. Сравнение использует сохранённые версии, а не mock-конфигурации.

## Отчёт

Экспорт содержит snapshot карты, границы и видимые слои, перечень средств по типам/эшелонам, количество, основные ТТХ, описание, детали МОГ, стоимость (или явно включённый режим скрытия), бюджет, предупреждения, источники данных и версию расчёта. PDF/print не считается доказательством, если он не построен из того же server payload.

## Критерии приёмки

- E2E на чистом пользователе создаёт проект, размещает МОГ, получает budget/constraint result, сохраняет вариант, перезагружает его, сравнивает с другим вариантом и выгружает отчёт.
- Скриншот/DOM-regression покрывает `1280×720` и `1440×960` для панелей, карты и legend.
- API-contract tests проверяют, что единый `projectVersion` передаётся через save, budget, compare и report.
